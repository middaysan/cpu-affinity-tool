# Windows rendering and CPU monitoring footprint

The Windows entrypoint explicitly selects WGPU / DirectX 12 and `MemoryHints::MemoryUsage`. Ordinary operation disables WGPU instance validation flags. These are fixed startup options, not user tuning settings. Linux keeps the existing Glow / OpenGL renderer; WGPU backend dependencies are scoped to Windows. The native window retains its ordinary application title, initially hidden/inactive/taskbar-free contract, tray restoration and hide-before-shutdown behavior.

Both themes share one set of text rasterization options. Bundled Inter fonts and these options are installed before the first UI frame; bounded preparation handles at most 32 glyph variants per pass and requests a 60 Hz cadence. Settled preparation requests no repaint. The local [epaint patch](../vendor/epaint/LOCAL-PATCH.md) recognizes equivalent default variation locations while preserving nondefault size/coordinate/target invalidation. Regression coverage checks unchanged atlas pixels at 100%, 125% and 175% scales.

The own process remains BelowNormal and pinned to its last representable logical CPU. After creating Tokio, only the GUI thread receives relative priority +1, with native readback and restoration on failure. Worker priorities and target-process launch affinity inheritance remain unchanged. The local [eframe patch](../vendor/eframe/LOCAL-PATCH.md) also provides opt-in frame attribution for debug profiling; that callback and the application probe are compiled out of ordinary releases. Debug MCP remains forbidden in release builds.

Contributor history keeps the same 8192 identity slots, sample capacity, f32 precision and lifetime ownership. An ordinary aligned entry uses a `u16` slot index and occupies eight bytes instead of twelve. The existing memory estimate/admission budget derives from its actual size. On twenty logical CPUs with 1800-second retention this saves 4,610,560 bytes of reserved numeric storage, independently of driver allocations. No collector or sampling interval is removed to obtain the renderer savings.

The earlier isolated same-source release comparison measured OpenGL at 234.96 MiB Private Bytes / 143.01 MiB working set / 9.51% of one CPU19 during actual long-table scrolling; DX12 measured 167.80 / 129.47 MiB / 7.03%. These are host observations, not universal bounds. Private Bytes and working set describe different memory quantities. Theme-change private memory reached a plateau in the short acceptance run; this is not a certification of leak freedom.

An accurately traced cold native frame still reached about 62 ms during startup, overlapping PDH initialization and scheduler waits. GUI-stage timing alone excludes that full native-frame cost. This migration retains the limitation; it does not promise every frame is below a fixed latency. Broader Windows 10, remote-session, software-adapter and GPU/driver combinations remain part of the manual release matrix. Startup graphics failures retain the existing error/crash-report handling.

The integrated branch comparison and exact tested commit are recorded in [the CPU19 report](cpu19-performance-probe.md). Final user-directed independent review and release approval remain separate from committing this implementation.
